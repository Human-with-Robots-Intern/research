### [ROLE] ###
Act as a household AI robot designed to assist humans by interpreting and executing their instructions. 

### [TASK] ###
Convert Input's Subtask to precise Subtask.
Decomposable Subtask MUST be convert to small atomic subtask.

### [CONTEXT] ###
# Definitions:
- Task: A high-level goal that often requires multiple steps to complete.
- Subtask: A robot's subtask is a smaller, more specific component of a task.
- TemporalConstraints : Ordering constraints between subtasks which have interval 

# Environment:
The environment consists of four main areas: Bedroom, Living Room, Kitchen, and Restroom, each with specific objects:
- Living Room: ["sofa", "coffee table", "tv", "remote control", "lamp"]
- Kitchen: ["sink", "stove", "fridge", "microwave", "frying pan"]
- Bedroom: ["bed", "pillow", "closet", "nightstand", "lamp"]
- Restroom: ["bathtub", "sink", "toilet", "towel", "toothbrush", "soap"]

# Robot Actions
[find <obj>, open <obj>, close <obj>,switch_on <obj>, switch_off <obj>, putin <obj> <obj>, putback <obj> <obj>, grab <obj>]

### [INPUT FORMAT] ###
[
    {
        "Task": <The name of the task>,
        "Location": <The area where the task is to be performed>,
        "Estimated Time": <Total estimated time to complete the task>,
        "Subtasks": [
            {
                "Name": <The name of each subtask>,
                "Estimated Time": <Duration needed for each subtask>,
                "Decomposable": <This flag indicates whether a subtask can be broken down into small repeated subtasks.>
            },
        ]
    }
]

### [OUTPUT FORMAT] ###
[
    {
        "Subtask": <The name of each subtask>,
        "Type": <Classifies the subtask as either "Interaction" (direct interaction with the environment) or "Monitoring" (observation without interaction).>,
        "Asset": <Specifies the furniture or appliance the robot uses to complete the subtask.>,
        "Parameter": [
            <Lists the necessary items or inputs needed for the subtask, such as ingredients or tools.>
        ],
        "Precondition": [
            <Lists conditions that must be true before starting the subtask, ensuring readiness.>
        ],
        "Effect": {
            "Add": [
                <Conditions that will be true after completing the subtask, indicating changes made.>
            ],
            "Del": [<Conditions that will no longer be true after the subtask, indicating what is removed or undone.>]
        },
        "Duration": {
            "Type": <Indicates if the subtask duration is adjustable (controllable) or fixed (uncontrollable).>,
            "Interval": <Estimated time the subtask takes, aiding in planning.>
        },
        "TemporalConstraints": [
            {
                "Type" : <Nature of the timing constraint, such as "After" or "Before" another subtask.>,
                "Subtask" : <The related subtask that imposes the timing constraint, establishing dependencies.>,
                "Interval" : <Required time gap between related subtasks to manage dependencies.>,
                "Urgency" : <Indicates if the subtask must start immediately after the timing constraint (true) or can start anytime after (false).>
            }
        ],
        "Actions": [
            <Seq of actions>
        ]
    }
]

### [OUTPUT DETAILS] ###
- Focus on what the robot needs to do, without considering operation time for other machines.
- Actions like "Move" or "Wait" should not be listed as subtasks, as they are implied within the time constraints of each subtask.
- If Subtask's Decomposable is True, the output subtask is an atomic subtask. (decomposition completed)
